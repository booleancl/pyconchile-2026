Cuando el LLM se equivoca

items.0.quantity
  Input should be greater than 0 [type=greater_than, input_value=0]

currency
  Input should be 'CLP' or 'USD' [type=literal_error, input_value='pesos']

customer
  Field required [type=missing]

Dónde

La ruta exacta: el primer producto, su cantidad.

Qué regla

Un tipo estable, sin parsear texto libre.

Y después

Reintentar con el modelo, enviándole el error.

12:45–13:30.Mensajes reales de Pydantic 2 sobre las respuestas rotas de la demo (abreviados: el mensaje completo trae además el tipo de dato y un enlace a la documentación del error). El valor de negocio no es solo detectar el error, sino describirlo de forma que una máquina pueda actuar: la ruta exacta, un tipo estable (greater_than, literal_error, missing) y el valor recibido. Ese texto se puede devolver al modelo para que corrija su respuesta; bibliotecas como Instructor hacen exactamente eso, reintentando cuando falla la validación. El JSON cortado también se rechaza con un error claro (json_invalid). Mostrar en vivo con la línea "first error" que imprime llm_parser.py.
