Tu código recibe texto. Antes de tocar el inventario, necesita un Order válido, o un error claro.

7:45–8:45. Presentar el caso antes de cualquier código: una empresa recibe pedidos por correo, un LLM los lee y devuelve un JSON con el pedido estructurado. El sistema guarda los datos en inglés, por eso las notas salen traducidas. Lo importante: lo que llega del modelo es solo texto. Puede venir bien, puede faltar un campo, puede traer una cantidad imposible o llegar cortado. Antes de descontar inventario o facturar, el programa necesita convertir ese texto en un objeto Order con tipos correctos, o rechazarlo con un error que explique qué falló. Ese paso es el que vamos a mirar por dentro.
