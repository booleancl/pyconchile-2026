En V1, cada campo de cada respuesta se valida paso a paso, con objetos de Python. En V2 se cruza la frontera una vez: entra texto, sale el objeto.

8:45–10:00. La teoría de la demo, en una sola idea. En V1, parse_raw primero usa json.loads (que es C, rápido) para crear diccionarios y listas de Python; después el código de validación recorre en Python cada campo de cada pedido: comprueba tipos, que la cantidad sea mayor que 0, que la moneda sea CLP o USD, convierte la fecha. Ese recorrido se repite en cada respuesta. En V2, model_validate_json entrega el texto a pydantic-core: el parseo y la validación ocurren en Rust, siguiendo el core schema que se construyó una sola vez a partir de las anotaciones, y Python recibe el objeto final. Conectar con la slide de delegar: es la misma idea de delegar, y la frontera se cruza una vez por respuesta, no una vez por campo. Matiz si preguntan: el Pydantic 1 de PyPI estaba compilado con Cython, así que su validación no era Python interpretado puro; aun así seguía trabajando con objetos de Python en cada paso.
